创建应用

手工创建不只是登记名称，还要一次性明确应用类型、可见租户、开通收费、客户端、入口/API/权限、文档和初始版本。

基础信息

这里决定应用的长期身份。`app_code` 创建后不建议修改。

必填

可见范围、开通方式与收费方式

可见范围只保留全部租户和指定租户。内部应用不特殊化，只是选择指定租户。

客户端形态

应用可拥有多个客户端。租户能下载或进入客户端，还要经过权益判断。

入口、API 与权限模板

创建应用时可先生成草稿入口。后续 Manifest 装载会覆盖或补齐真实资产。

资产类型编码名称绑定权限状态

ENTRYai-project.requirement需求管理ai_project:req:view规划中
APIai-project.query项目查询 APIai_project:api:query规划中
PERMISSIONai_project:req:generateAI 生成需求--规划中

文档池与初始版本

手工创建应用时就要建立知识资产和版本骨架，避免只有菜单没有需求依据。

确认创建

确认后生成应用草稿、客户端草稿、入口/API/权限草稿、文档池和初始版本。不直接发布正式版。

草稿
1 应用主档sys_app + 指定租户可见关系
2 运行资产client / entry / api / permission
3 套餐资源生成 APP、CLIENT、ENTRY 草稿
4 知识资产文档池 + 初始版本
这一步只是静态原型。真实实现时，创建接口需要事务保存这些草稿，并写入应用审计日志。

创建摘要

  • 应用AI 项目管理系统
  • app_codeai-project-manager
  • 可见范围指定租户
  • 收费方式免费
  • 试用策略不限期
  • 客户端PC Web / API

创建后进入

  • 应用详情概览
  • 待补配置套餐资源
  • 待确认文档发布
  • 下一步Manifest 装载或手工完善
建议创建后默认状态为草稿/规划中，避免半成品应用直接对租户可见。
