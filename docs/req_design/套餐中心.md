# 套餐中心

## 1. 功能定位

套餐中心用于管理 SaaS 商业化能力，包括套餐、功能点、配额项、套餐功能矩阵、套餐配额和租户订阅。它决定主体购买后能使用哪些菜单、按钮、服务能力以及能使用多少资源。

套餐中心是平台侧能力，不应开放给普通租户。它位于权限体系之上：套餐控制租户买了什么，角色权限控制用户能做什么，数据权限控制用户能看什么。

## 2. 功能目标

- 建立平台可售套餐体系。
- 将菜单、操作和服务能力纳入功能矩阵。
- 将用户数、公司数、业务单元数等资源纳入配额控制。
- 支撑主体订阅套餐、升级、降级和配额覆盖。
- 支撑运行时对功能和配额进行统一校验。

## 5. 页面与交互设计

### 5.1 页面入口

系统管理 / 套餐中心。

### 5.2 页面布局

页面包括套餐概览区、查询操作区、套餐列表区、套餐详情区、功能矩阵区、配额配置区、租户绑定区、功能点弹窗、配额项弹窗、租户覆盖弹窗和配额使用弹窗。

### 5.3 查询与筛选

当前支持按套餐编码或名称搜索。是否支持按套餐类型、状态、计费周期、价格区间筛选为（当前实现未覆盖，按后续增强处理）。

### 5.4 列表展示

套餐列表展示套餐编码、套餐名称、套餐类型、计费周期、价格、状态、是否默认、排序、说明和绑定租户情况等信息。能力矩阵展示功能分类、功能开关、关联配额和各套餐配置值。

### 5.5 新增/编辑表单

套餐基础表单维护套餐编码、套餐名称、套餐类型、计费周期、价格、状态、是否默认、排序和说明。

功能点表单维护功能编码、功能名称、功能类型、父级能力、状态和说明。

配额项表单维护配额编码、配额名称、配额类型、周期类型、单位、状态和说明。

租户订阅表单维护主体、套餐、订阅状态、开始时间、结束时间、试用结束时间、自动续费和冻结原因。

### 5.6 操作按钮

页面支持刷新、新增套餐、编辑套餐、复制套餐、归档套餐、新增功能点、编辑功能点、新增配额项、编辑配额项、配置功能矩阵、保存套餐能力、保存套餐配额、绑定租户、配置租户覆盖和查看配额使用。

## 6. 业务规则设计

### 规则 1：套餐编码必须稳定唯一

- 规则说明：套餐编码是套餐识别和商业配置的重要标识。
- 触发场景：新增或编辑套餐。
- 处理逻辑：系统应校验编码非空且不重复。
- 异常情况：已归档套餐编码释放策略以逻辑删除规则为准。

### 规则 2：功能点来源于菜单、操作和服务能力

- 规则说明：套餐不直接绑定角色权限，而是绑定功能点。
- 触发场景：维护菜单或权限、配置套餐矩阵。
- 处理逻辑：可套餐化且非平台专属的菜单、操作会进入功能点池；服务和配置类能力也可作为功能点维护。
- 异常情况：主体管理、套餐中心、系统监控等平台专属能力不得进入租户套餐。

### 规则 3：配额只对启用功能生效

- 规则说明：没有开放某功能时，关联配额不应单独生效或展示为可配置能力。
- 触发场景：配置套餐功能矩阵、配置租户配额覆盖。
- 处理逻辑：系统按功能矩阵过滤可配置配额；运行时也按功能与配额联合校验。
- 异常情况：历史已保存但功能关闭的配额覆盖如何清理（当前实现未覆盖，按后续增强处理）。

### 规则 4：租户覆盖优先于套餐默认值

- 规则说明：同一套餐可以给不同主体配置不同资源额度。
- 触发场景：主体创建套餐配置、租户配额覆盖、运行时配额校验。
- 处理逻辑：系统优先使用租户覆盖值，没有覆盖时使用套餐默认值。
- 异常情况：覆盖值低于已使用量时需要明确保存策略。

### 规则 5：套餐删除必须为归档

- 规则说明：套餐涉及租户订阅历史，不能物理删除。
- 触发场景：平台管理员删除套餐。
- 处理逻辑：系统执行逻辑归档，保留历史订阅和审计记录。
- 异常情况：已被租户订阅的套餐是否允许归档（当前实现未覆盖，按后续增强处理）。

## 7. 数据逻辑说明

套餐由功能点和配额组成。功能点可表示菜单入口、按钮操作、接口能力、服务能力或配置能力。配额用于表达资源上限或周期用量。

一个主体当前绑定一个有效订阅。订阅关联套餐，同时允许对功能和配额做租户级覆盖。运行时最终结果由套餐功能、租户覆盖、角色权限和数据权限共同决定。

## 8. 权限与范围设计

套餐中心为平台专属能力，不进入租户功能池。平台管理员可维护套餐、功能、配额和租户绑定。租户侧只能消费套餐结果，不应修改套餐定义。

套餐功能控制的是租户范围，不能替代角色权限。即使套餐开放某按钮，用户仍需角色权限才可使用。

## 9. 状态与生命周期

| 状态 | 含义 | 可执行操作 | 影响 |
|---|---|---|---|
| 启用 | 套餐可被绑定和使用 | 编辑、配置、复制、停用、归档 | 主体可订阅该套餐 |
| 停用 | 套餐不可继续作为正常可选项 | 编辑、启用、复制、归档 | 新订阅或变更应受限 |
| 已归档 | 套餐逻辑删除 | 历史查看（当前实现未覆盖，按后续增强处理） | 列表默认不展示 |

订阅状态包括试用、正常、欠费、冻结、到期、取消等，具体流转策略（当前实现未覆盖，按后续增强处理）。

## 10. 异常与边界场景

- 套餐编码重复。
- 功能点编码重复。
- 配额编码重复。
- 套餐未启用但被选择绑定。
- 套餐没有任何功能时租户无法正常使用。
- 功能关闭后仍存在关联配额覆盖。
- 配额值为 0、-1、正数时含义混淆。
- 已订阅套餐被停用或归档。
- 降级套餐后用户已有权限超出套餐范围。

## 11. 与其他功能的关系

- 主体管理通过套餐中心为主体绑定订阅和配额覆盖。
- 菜单管理中的可套餐化菜单和操作会同步到功能点。
- 角色权限只能在套餐允许范围内分配和生效。
- 组织架构、用户管理、业务单元等创建动作受配额控制。
- 操作日志记录套餐配置变更行为（当前实现未覆盖，按后续增强处理）。

## 12. 测试关注点

| 测试点 | 验收说明 |
|---|---|
| 新增套餐 | 套餐基础信息可保存，编码唯一校验生效 |
| 配置功能 | 勾选功能后租户可见能力发生变化 |
| 配置配额 | 配额值 0、-1、正数含义正确 |
| 功能配额联动 | 未启用功能时不展示或不允许配置关联配额 |
| 租户覆盖 | 覆盖配额优先于套餐默认值 |
| 套餐变更 | 主体切换套餐后菜单、按钮和配额及时变化 |
| 平台专属过滤 | 主体管理、套餐中心不进入租户套餐功能池 |
| 归档 | 套餐归档后列表默认不展示且历史可追溯 |

## 14. 后续优化建议

当前已具备套餐、功能点、配额、能力矩阵、租户订阅和租户覆盖等 SaaS 商业化底座能力。

建议增强套餐版本变更记录、套餐差异对比、订阅变更审批和租户超配额预警。

暂不建议加入在线支付、优惠券、发票、自动扣款等复杂计费能力，避免套餐中心过早变成账务系统。
