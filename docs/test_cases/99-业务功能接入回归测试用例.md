# 业务功能接入回归测试用例

## 1. 文档定位

本文档不是某个系统管理菜单的单点用例，而是所有新业务模块接入 SaaS 底座后的准入回归清单。业务模块除了验证自身业务逻辑，还必须证明已正确接入菜单权限、按钮权限、角色权限、套餐功能矩阵、配额限制、tenant 隔离、组织/业务单元数据权限、逻辑删除、字典参数和日志审计。

## 2. 适用范围

- 新增业务菜单、业务按钮、后端服务能力、导入导出能力、AI 能力或开放 API。
- 修改套餐、权限、数据权限、配额、tenant 上下文、日志审计等横切能力。
- 业务模块上线前验收、版本发布前回归和 AI 编程助手修改后的自检。

## 3. 前置条件

- 至少准备两个普通主体和一个平台主体。
- 至少准备 BASIC、PRO 两种套餐，并确保功能和配额存在差异。
- 至少准备平台管理员、租户管理员、只读用户、无权限用户。
- 业务模块已完成菜单和操作点定义，并已接入前端路由和后端接口。
- 业务模块涉及的字典、参数、配额、审计事件已经初始化或明确标记【待确认】。

## 4. 业务功能接入回归用例

| 用例编号 | 优先级 | 测试场景 | 前置条件 | 操作步骤 | 预期结果 |
|---|---|---|---|---|---|
| TC-BIZ-REG-001 | P0 | 主体创建后接入业务模块 | 平台管理员、套餐、功能点、配额定义已准备 | 创建主体第一步，创建主管理员和默认公司 | 主体存在，主管理员可登录；未配置套餐时业务菜单不可越权使用 |
| TC-BIZ-REG-002 | P0 | 主体配置套餐后菜单生效 | 主体已创建，套餐含部分菜单和按钮 | 保存套餐订阅、起止时间、配额覆盖后用主管理员登录 | 只展示套餐允许且角色允许的菜单；平台专属菜单不展示 |
| TC-BIZ-REG-003 | P0 | 新增业务菜单接入权限链路 | 新增业务模块已定义菜单和操作点 | 检查菜单与权限定义、套餐功能映射、租户菜单、角色授权 | 四层链路一致，缺任一层时前端不展示或后端拒绝 |
| TC-BIZ-REG-004 | P0 | 按钮权限与套餐双重收敛 | 套餐允许菜单但不允许某操作，角色允许该操作 | 登录页面并直接调用操作接口 | 按钮不展示或不可用；后端通过 feature/operation 校验拒绝 |
| TC-BIZ-REG-005 | P0 | 套餐变更即时生效 | 租户从 BASIC 升级到 PRO 或从 PRO 降级到 BASIC | 变更套餐后刷新能力上下文、重新打开业务页面 | 新增功能及时出现，降级功能及时消失；直接接口调用同步拒绝 |
| TC-BIZ-REG-006 | P0 | 配额覆盖优先生效 | 同一套餐下主体 A 用户席位 50，主体 B 用户席位 500 | 分别创建用户到接近上限 | A 按 50 拦截，B 按 500 拦截；均不使用 tenant.max_users 旧字段判断 |
| TC-BIZ-REG-007 | P0 | 功能关闭后配额不展示不生效 | 套餐关闭导入或 API Key 功能 | 查看套餐配额和租户配额配置 | 关联配额不应展示或生效；历史覆盖值不应造成隐藏功能可用 |
| TC-BIZ-REG-008 | P0 | 业务数据 tenant 隔离 | 主体 A/B 均创建同类业务数据 | A 用户查询列表、详情、编辑和删除 B 数据 id | 查询不可见，详情/编辑/删除被拒绝或查无数据 |
| TC-BIZ-REG-009 | P0 | 业务数据权限接入 | 业务模块支持组织或业务单元数据范围 | 不同角色设置 ORG/ORG_SUB/SELF/CUSTOM 后查询 | 返回数据严格符合范围，不能先查全量后前端过滤 |
| TC-BIZ-REG-010 | P0 | 逻辑删除接入 | 业务模块支持删除 | 删除业务数据后查询列表、详情、日志、唯一编码复用 | 列表默认不可见，数据库保留 deleted_at 或等价状态，审计可追溯，唯一键按规则释放 |
| TC-BIZ-REG-011 | P1 | 字典参数接入 | 业务模块使用下拉选项或开关参数 | 修改租户字典覆盖和参数覆盖后进入业务页面 | 业务页面读取当前租户有效值，不误用平台默认值 |
| TC-BIZ-REG-012 | P1 | 日志审计接入 | 业务模块有新增、编辑、删除、导入导出等操作 | 执行关键操作后查询操作日志 | 日志记录操作人、主体、模块、动作、IP、时间和摘要；租户仅可查看本主体 |
| TC-BIZ-REG-013 | P1 | 配额不足统一提示 | 业务模块触发套餐或席位上限 | 执行新增或导入 | 页面提示“配额不足，请联系管理员”或等价统一文案，提示不被弹窗遮罩遮盖 |
| TC-BIZ-REG-014 | P1 | 前端路由守卫 | 用户无业务菜单权限但知道 URL | 直接访问业务路由 | 跳转首页或无权限状态，不加载敏感数据 |
| TC-BIZ-REG-015 | P1 | API 越权兜底 | 绕过前端直接调用业务 API | 使用无权限、套餐不允许、跨租户三类 token 调用 | 后端分别按权限、套餐、tenant 隔离拒绝 |


## 5. 上线准入清单

| 准入项 | 验收说明 | 优先级 |
|---|---|---|
| 菜单权限 | 菜单来自后端权限数据，前端不得硬编码角色可见性 | P0 |
| 按钮权限 | 按钮权限码前后端一致，直接调接口也会被拒绝 | P0 |
| 套餐矩阵 | 功能点已进入套餐矩阵，平台专属能力不进入租户套餐 | P0 |
| 配额限制 | 配额来源为 tenant_quota_override > saas_plan_quota，超过限制禁止新增 | P0 |
| 数据隔离 | 所有租户内查询、详情、更新、删除都带 tenant 约束 | P0 |
| 数据权限 | 组织/业务单元/本人/自定义范围在查询层生效 | P0 |
| 逻辑删除 | 业务数据不物理删除，删除后历史和审计可追溯 | P0 |
| 字典参数 | 业务表单和规则读取当前租户有效字典和参数 | P1 |
| 日志审计 | 关键写操作、导入导出和敏感变更记录操作日志 | P1 |
| 异常体验 | 权限、套餐、配额、数据不存在等异常提示清晰且不泄露内部信息 | P1 |

## 6. 待确认事项

| 类型 | 内容 | 影响 |
|---|---|---|
| 套餐待确认 | 新业务服务类能力与菜单/按钮功能点的映射颗粒度 | 影响套餐售卖和测试边界 |
| 配额待确认 | 每类业务资源是否需要单独配额项和使用量统计 | 影响上线准入 |
| 数据权限待确认 | 业务模块是否采用组织、业务单元、本人或混合范围 | 影响查询测试设计 |
| 日志待确认 | 业务模块必须记录的审计事件清单 | 影响合规验收 |
