# 套餐中心 - 测试用例

## 1. 测试目标

验证 `套餐中心` 在当前系统管理模块中的页面、接口、数据、权限、租户隔离、逻辑删除和审计行为是否符合当前实现与文档约定。重点关注：

- 套餐基本信息、功能矩阵、配额定义和租户订阅联动
- 功能关闭后关联配额不应出现在套餐配置中
- 配额 -1/0/正数语义正确，覆盖值优先于套餐默认值
- 套餐变更后菜单、按钮、后端功能校验和配额校验及时生效

## 2. 测试范围

本模块测试覆盖页面进入、查询筛选、列表或树形展示、新增、编辑、逻辑删除/归档、状态变更、权限控制、数据权限、接口校验、数据库约束和日志审计。当前实现未提供的能力在对应用例备注中标记【待确认】或“不涉及”。

## 3. 前置条件

- 已部署可访问的后端 API、前端管理端、PostgreSQL 和 Redis。
- 已准备平台管理员、租户管理员、普通用户三类账号。
- 已准备至少两个主体，用于验证跨主体隔离。
- 已准备启用/禁用、已引用、已归档三类基础数据。
- 已按 `internal/infrastructure/persistence/postgres/migrations/` 初始化菜单、权限、套餐、字典和参数基础数据。
- 执行权限相关用例前，需要分别准备“有权限账号”和“无权限账号”。

## 4. 测试数据

| 数据类型 | 数据说明 | 用途 |
|---|---|---|
| 平台管理员 | 平台主体下具备系统管理全量权限的账号 | 验证平台级菜单和跨主体能力 |
| 租户管理员 | 普通主体下具备本主体管理权限的账号 | 验证租户隔离和租户内维护能力 |
| 普通用户 | 仅具备少量菜单或无按钮权限 | 验证菜单、按钮和接口权限拒绝 |
| 主体 A / 主体 B | 两个相互独立的租户主体 | 验证跨主体数据不可见 |
| 启用/禁用数据 | 同一对象准备不同状态 | 验证状态过滤和状态影响 |
| 已引用数据 | 被用户、角色、组织、业务数据引用的对象 | 验证删除/归档引用限制 |
