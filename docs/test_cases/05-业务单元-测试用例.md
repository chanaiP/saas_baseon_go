# 业务单元 - 测试用例

## 1. 测试目标

验证业务单元模块按新口径工作：

```text
类型 -> 分组 -> 列表
```

同时验证父子关系、关联关系、自定义属性模板、负责组织/负责人、权限、套餐和租户隔离。

## 2. 前置条件

- 已执行最新迁移。
- 已存在业务单元字典。
- 字典一级项包含门店、仓库、项目。
- 门店下二级项包含抖音、京东、小红书、线下。
- 仓库下二级项包含华东、华南。
- 已准备有权限账号和无权限账号。
- 已准备两个主体用于租户隔离验证。
- 前端运行在 `5177`，后端 API 运行在 `8081`。

## 7. 自定义属性模板

| 用例 | 场景 | 操作 | 预期 |
|---|---|---|---|
| TC-BU-ATTR-001 | 类型通用模板 | 维护门店/空分组模板 | 门店下未配置专用模板的分组加载该模板 |
| TC-BU-ATTR-002 | 分组专用模板 | 维护门店/抖音模板 | 新增抖音门店优先加载抖音模板 |
| TC-BU-ATTR-003 | 无模板 | 类型和分组均无模板 | 自定义属性区域为空 |
| TC-BU-ATTR-004 | 字段渲染 | 模板含 text、number、date、select、switch | 前端渲染对应控件 |
| TC-BU-ATTR-005 | 必填校验 | 必填字段为空 | 前端或后端拒绝保存 |
| TC-BU-ATTR-006 | JSON 保存 | 填写模板字段后保存 | `attrs` 保存为 JSON 对象 |
| TC-BU-ATTR-007 | 编辑回显 | 编辑已保存业务单元 | 按 `attrs` 回填模板字段 |

## 9. 权限、菜单、套餐

| 用例 | 场景 | 操作 | 预期 |

| TC-BU-PERM-004 | 无删除权限 | 无 `business_unit:delete` | 不显示归档按钮，接口 403 |
| TC-BU-PERM-005 | 无关系权限 | 无 `business_unit:relation_manage` | 保存关联关系接口 403 |
| TC-BU-PERM-006 | 无责任方权限 | 无 `business_unit:actor_manage` | 保存负责组织/负责人接口 403 |
| TC-BU-PERM-007 | 无模板权限 | 无 `business_unit:attr_template_manage` | 模板维护接口 403 |
| TC-BU-PERM-008 | Manifest 装载 | 重启或装载系统管理应用 | 权限、菜单、套餐功能点存在且不覆盖人工配置 |

## 10. 租户隔离

| 用例 | 场景 | 操作 | 预期 |
|---|---|---|---|
| TC-BU-TENANT-001 | 列表隔离 | 主体 A 查询业务单元 | 不返回主体 B 数据 |
| TC-BU-TENANT-002 | 编辑隔离 | 主体 A 编辑主体 B 业务单元 ID | 返回不存在或拒绝 |
| TC-BU-TENANT-003 | 父级隔离 | 主体 A 设置主体 B 业务单元为父级 | 后端拒绝 |
| TC-BU-TENANT-004 | 关联隔离 | 主体 A 关联主体 B 业务单元 | 后端拒绝 |
| TC-BU-TENANT-005 | 责任方隔离 | 主体 A 保存主体 B 用户/组织 | 后端拒绝 |

## 11. 自动化验证

必须执行：

```bash
go test ./internal/interfaces/http/handlers
go test ./...
cd frontend && npm run build
git diff --check
```

浏览器验收：

- 打开 `http://127.0.0.1:5177/business-units`。
- 确认页面为类型、分组、列表。
- 确认右上分组能显示抖音、京东等统计。
- 确认新增业务单元可以加载模板并保存 attrs JSON。
- 确认负责组织/负责人使用 `OrgUserPicker`。
