# 13-C 端个人空间测试用例

## 1. 注册与登录

| 编号 | 场景 | 前置条件 | 操作 | 预期 |
|---|---|---|---|---|
| C01 | C 端注册成功 | 账号、手机号、邮箱未被占用 | 调用 `POST /api/auth/register` | 返回 token；创建 `account`、`user_identity`、`tenant_type=personal` 空间、`personal_owner` 成员 |
| C02 | 重复账号注册 | 已存在相同 `login_account` | 再次注册 | 返回业务错误，不创建重复账户 |
| C03 | 重复手机号注册 | 已存在相同手机号 | 再次注册 | 返回业务错误，不创建重复账户 |
| C04 | 注册后直接进入个人空间 | 注册成功 | 调用 `/api/users/me` | 返回 `tenant_type=personal`、`member_type=personal_owner` |
| C05 | Account 登录个人空间 | 已有个人账号 | 账号/手机号/邮箱登录 | 登录成功，token 绑定个人空间 |
| C06 | 历史企业用户登录兼容 | 旧 `app_user` 未绑定 `account_id` | 使用旧账号登录 | 登录成功，并补齐 `account_id`、`identity_user_id` |

## 2. 菜单与权限范围

| 编号 | 场景 | 前置条件 | 操作 | 预期 |
|---|---|---|---|---|
| C07 | 个人空间菜单过滤 | 个人用户登录 | 拉取菜单包并打开首页 | 不显示主体管理、套餐中心、用户管理、角色权限等企业/平台菜单 |
| C08 | 个人可见数据中心 | 个人用户登录且拥有个人权限 | 打开 `/data-center` | 页面可访问，接口返回 200 |
| C09 | 个人禁止企业管理能力 | 个人用户登录 | 访问 `/users`、`/tenants` | 前端跳回首页或后端返回 403 |
| C10 | 企业空间不受个人菜单影响 | 企业管理员登录 | 打开系统管理与数据中心 | 企业菜单按原有配置展示 |
| C11 | 平台管理员治理全局菜单 | 平台管理员登录 | 打开菜单管理 | 可看到平台、企业、个人相关菜单范围配置 |
| C12 | 普通平台空间成员不越权 | 平台空间普通成员登录 | 打开系统管理 | 仅展示已授权菜单，不因平台空间自动获得平台管理员能力 |

## 3. 空间范围配置

| 编号 | 场景 | 操作 | 预期 |
|---|---|---|---|
| C13 | `platform_only` | 将菜单设为仅平台 | 仅平台空间可见；企业/个人不可见 |
| C14 | `enterprise_only` | 将菜单设为仅租户 | 仅企业空间可见 |
| C15 | `personal_only` | 将菜单设为仅个人 | 仅个人空间可见 |
| C16 | `all` | 将菜单设为不限 | 平台、企业、个人均可见 |
| C17 | `platform_enterprise` | 将菜单设为平台和租户 | 平台、企业可见，个人不可见 |
| C18 | `enterprise_personal` | 将菜单设为租户和个人 | 企业、个人可见，平台普通视角不可见 |
| C19 | `platform_personal` | 将菜单设为平台和个人 | 平台、个人可见，企业不可见 |

## 4. 数据隔离

| 编号 | 场景 | 操作 | 预期 |
|---|---|---|---|
| C20 | 个人空间数据隔离 | 个人 A 和个人 B 分别创建业务数据 | 双方只看到自己的数据 |
| C21 | 个人不能伪造租户 | 个人用户传入其他 `tenant_id` | 后端仍使用 token 中的 `tenant_id` |
| C22 | 企业与个人共用数据中心 API | 企业和个人分别访问 `/api/data-center/**` | 均可访问，但数据按各自 `tenant_id` 隔离 |

## 5. 前端回归

| 编号 | 场景 | 操作 | 预期 |
|---|---|---|---|
| C23 | 深色主题个人空间 | 个人登录后切换深色主题 | 菜单、表格、卡片、空状态无错位、无不可读文字 |
| C24 | 浅色主题个人空间 | 个人登录后切换浅色主题 | 页面无样式断层、无控制台错误 |
| C25 | 应用中心菜单归组 | 平台管理员打开菜单管理 | 应用中心菜单不混入系统管理二级菜单 |
| C26 | Ai 经营决策中心菜单归组 | 平台管理员点击 Ai 经营决策中心 | 展示经营看板、标准数据等业务菜单，不展示主体管理 |

## 6. 建议自动化命令

```bash
go test ./internal/interfaces/http/handlers
cd frontend && npm run build
git diff --check
```

浏览器巡检建议覆盖：

- 平台管理员：系统管理、应用中心、AI 能力中心、第三方集成中心、Ai 经营决策中心。
- 企业管理员：数据中心、用户管理、角色权限、组织架构。
- 个人用户：首页、数据中心、个人中心、禁止访问的企业管理页。
