# 平台租户与租户侧增强 TODO

本文档收拢当前不阻断平台侧应用资产闭环、但后续需要产品化确认和实现的租户侧增强点。

## 1. 租户管理员查看本主体基础信息

- [ ] 明确租户管理员是否允许查看本主体基础信息。
- [ ] 若允许，设计独立入口，例如“我的主体 / 企业信息”，避免混入平台端“主体管理”。
- [ ] 明确可查看字段：主体名称、主体编码、状态、当前套餐、到期时间、配额使用、主管理员信息等。
- [ ] 明确是否支持租户管理员申请修改主体资料。
- [ ] 补后端接口权限：只能查看当前登录主体，不允许 query/body/path 伪造 `tenant_id`。
- [ ] 补前端页面和租户隔离测试。

## 2. 主体套餐配置状态标识

- [ ] 主体列表增加套餐或开通状态标识。
- [ ] 明确状态口径：未配置套餐、试用中、已订阅、已过期、已停用。
- [ ] 主体详情展示当前套餐、订阅有效期、配额摘要和覆盖情况。
- [ ] 未完成套餐配置的主体在列表和详情中给出运营提示。
- [ ] 补接口返回字段、前端展示和测试。

## 3. 租户菜单覆盖的实施场景

- [ ] 明确产品、实施、客户成功人员是否能为指定租户维护菜单覆盖。
- [ ] 设计入口位置，建议放在平台端主体详情下的“租户菜单配置”，不与普通菜单管理混用。
- [ ] 明确可覆盖字段：显示名称、图标、排序、显示/隐藏、启停。
- [ ] 禁止覆盖平台专属、不可租户编辑或 Manifest 保护资源。
- [ ] 覆盖变更必须记录 `source/source_ref` 和审计日志。
- [ ] 补菜单覆盖保存、恢复默认、权限校验和缓存失效测试。

## 4. 数据权限完整覆盖联调

- [ ] 梳理各模块 list/detail/export 是否统一接入数据权限过滤。
- [ ] 优先覆盖用户、组织架构、业务单元、登录日志、操作日志、导出接口。
- [ ] 验证 SELF、ORG、ORG_SUB、CUSTOM、BU、ALL 等数据范围。
- [ ] 验证平台管理员跨租户访问仍受显式权限控制并记录审计。
- [ ] 补跨租户数据准备和接口回归测试。
- [ ] 新增业务应用前，必须确认该应用的业务数据查询默认接入 tenant scope 和数据权限。
