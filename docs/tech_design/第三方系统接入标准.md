# 第三方系统接入标准

## 1. 文档定位

本文档约束所有外部平台、第三方 SaaS、开放 API、Webhook、OAuth 授权、数据同步和网关代理类接入。企业微信、钉钉、飞书、CRM、ERP、电商平台、支付平台、消息平台和自研外部系统均必须按此标准接入。

第三方系统接入必须通过 `integration-center` 治理，不得绕过第三方集成中心直接在业务模块里散写授权、密钥、Webhook、同步任务或外部 API 调用。

新增接入前必须同时阅读：

- `AGENTS.md`
- `CLAUDE.md`
- `docs/tech_design/业务开发标准.md`
- `docs/tech_design/应用中心接入强制规则.md`
- `docs/apps/integration-center.md`
- 本文档

## 2. 核心原则

- 第三方平台不是底座应用本身；底座应用统一为 `integration-center`，外部平台以 `platform_code` 管理。
- 每个外部平台必须有稳定唯一的 `platform_code`，例如 `wecom`、`dingtalk`、`feishu`。
- 每个服务商应用必须有稳定唯一的 `provider_app_code`，例如 `wecom-suite-standard`。
- 每个租户授权实例必须落到租户连接，不得只保存在前端、本地配置或业务模块私表。
- 密钥、token、永久授权码和 Webhook secret 不得明文入库；数据库只保存 `credential_ref`。
- 接入链路必须可审计、可重试、可停用、可解绑、可按租户隔离。
- 第三方数据进入底座前必须有来源标识、外部 ID、同步批次、幂等键和冲突策略。
- 第三方回调和同步不得绕过套餐、权限、配额、租户边界和审计。

## 3. 标准对象模型

第三方系统接入必须按以下对象建模：

| 层级 | 表或概念 | 说明 |
|---|---|---|
| 外部平台 | `integration_platforms` | 企业微信、钉钉、飞书等平台主档 |
| 平台能力 | `integration_platform_capabilities` | 通讯录同步、审批事件、消息发送等能力 |
| 服务商应用 | `integration_provider_apps` | 平台侧创建的具体应用、套件或 API client |
| 应用能力 | `integration_provider_app_capabilities` | 服务商应用开放哪些平台能力 |
| 租户连接 | `integration_tenant_connections` | 某租户授权绑定的某个外部企业、店铺、账号或组织 |
| 租户能力 | `integration_tenant_capabilities` | 该租户连接实际启用的能力 |
| 同步任务 | `integration_sync_jobs` | 全量、增量、补偿同步任务 |
| 同步记录 | `integration_sync_records` | 外部对象同步原始记录和处理结果 |
| Webhook 事件 | `integration_webhook_events` | 回调原始事件、幂等、重试和死信 |
| 调用日志 | `integration_api_call_logs` | 外部 API 调用、网关代理和失败审计 |
| 配额 | `integration_quota_policies` / `integration_quota_usages` | 连接数、调用量、同步记录数等限制 |

禁止新增第三方接入时绕过上述模型另建独立授权体系。业务模块可以保存自己的业务结果，但授权、token、Webhook、同步运行态必须归口第三方集成中心。

## 4. 命名规范

### platform_code

规则：

- 小写字母、数字、短横线。
- 一经上线不得改名。
- 不得使用中文、供应商营销名或环境名。

示例：

| 平台 | platform_code |
|---|---|
| 企业微信 | `wecom` |
| 钉钉 | `dingtalk` |
| 飞书 | `feishu` |
| Salesforce | `salesforce` |
| 用友 YonBIP | `yonyou-yonbip` |

### provider_app_code

规则：

- 推荐格式：`{platform_code}-{app_type}-{env}`。
- 同一外部平台多套应用必须拆开。
- 生产、沙箱、测试不得共用同一个 code。

示例：

| 场景 | provider_app_code |
|---|---|
| 企业微信第三方标准应用生产 | `wecom-suite-prod` |
| 企业微信第三方标准应用沙箱 | `wecom-suite-sandbox` |
| 钉钉 ISV 应用生产 | `dingtalk-isv-prod` |
| 飞书企业自建应用生产 | `feishu-internal-prod` |

### capability_code

规则：

- 必须描述能力，不描述页面。
- 同一平台内唯一。
- 数据同步能力按对象命名。

示例：

| 能力 | capability_code |
|---|---|
| 组织架构同步 | `org_sync` |
| 成员同步 | `user_sync` |
| 部门同步 | `department_sync` |
| 通讯录事件 | `contact_event` |
| 审批事件 | `approval_event` |
| 消息发送 | `message_send` |

## 5. 接入模式

每个第三方平台接入前必须声明接入模式，可以组合使用：

| 模式 | 说明 | 必填设计 |
|---|---|---|
| OAuth / 安装授权 | 租户管理员跳转第三方授权 | state、防重放、授权主体、token/ref、解绑 |
| Webhook / 回调 | 第三方推送事件 | 验签、解密、幂等、重试、死信 |
| Data Sync | 主动拉取或推送数据 | 游标、批次、冲突、补偿、配额 |
| Gateway Proxy | 通过底座代理调用第三方 API | path 白名单、token 注入、限流、审计 |
| Manual Credential | 平台人工配置密钥引用 | credential_ref、轮换、连通性检测 |

未声明接入模式的第三方系统不得上线。

## 6. 凭证与密钥

允许入库：

- `credential_ref`
- 脱敏后的凭证摘要
- 过期时间
- 凭证状态
- 授权主体 ID 和名称

禁止入库：

- `client_secret`
- `suite_secret`
- `access_token`
- `refresh_token`
- `permanent_code`
- `EncodingAESKey`
- Webhook secret
- 真实生产连接串

推荐凭证引用：

```text
vault://integration/{platform_code}/{provider_app_code}
vault://integration/{platform_code}/{provider_app_code}/tenant/{tenant_id}
secret://integration/{platform_code}/{provider_app_code}
env://INTEGRATION_{PLATFORM}_{APP}_SECRET
```

凭证轮换必须支持：

- 新旧凭证并存一个回滚窗口。
- 轮换后执行连通性检测。
- 失败时不覆盖旧可用凭证。
- 审计记录不得包含真实密钥。

## 7. 租户绑定标准

每个租户绑定第三方系统时，必须写入 `integration_tenant_connections`。

必填字段语义：

| 字段 | 标准含义 |
|---|---|
| `tenant_id` | 本系统租户 ID，不得来自前端伪造 |
| `platform_id` | 外部平台 |
| `provider_app_id` | 服务商应用 |
| `connection_name` | 展示名称，例如企业名称、店铺名称 |
| `auth_subject_type` | 授权主体类型，例如 `corp`、`shop`、`account` |
| `auth_subject_id` | 第三方主体 ID，例如企业微信 `corp_id` |
| `auth_subject_name` | 第三方主体名称 |
| `auth_scope` | 实际授权 scope JSON |
| `auth_status` | `pending`、`authorized`、`failed`、`expired`、`revoked` |
| `connection_status` | `connected`、`paused`、`failed`、`inactive`、`not_connected` |
| `token_credential_ref` | 租户级 token 或永久授权凭证引用 |

同一个租户不允许重复绑定同一个外部主体，唯一口径为：

```text
tenant_id + provider_app_id + auth_subject_type + auth_subject_id
```

重复授权必须更新原连接，不得生成脏连接。

解绑要求：

- 不物理删除连接。
- `auth_status=revoked`。
- `connection_status=inactive`。
- `token_status=revoked`。
- 停止同步任务。
- 保留审计和历史同步记录。

## 8. OAuth / 授权标准

所有授权流程必须具备：

- `state` 随机值。
- `state` 与当前用户、租户、服务商应用、回调地址绑定。
- `state` 只能使用一次。
- `state` 必须有过期时间。
- callback 中返回错误时必须落审计。
- token exchange 不得返回明文 token 给前端。
- token exchange 成功后必须返回 `credential_ref`。

授权成功后必须创建或更新租户连接，并触发必要的初始化任务，例如通讯录全量同步。

第三方平台如果不是标准 OAuth2，不得硬套通用 OAuth；必须实现平台专用 adapter。

## 9. Webhook / 回调标准

Webhook 接入必须实现：

- URL 验证或握手。
- 签名校验。
- 时间戳防重放。
- 幂等键。
- payload 摘要。
- 原始事件落库。
- 异步处理。
- 失败重试。
- 死信状态。
- 处理结果审计。

不同平台的验签算法必须放到平台专用 adapter 中，不得把平台差异写死在通用 handler。

事件处理原则：

- Webhook handler 只做验签、解密、幂等和落库。
- 复杂业务处理必须异步 worker 执行。
- 回调事件不得直接绕过同步任务写业务主表。
- 删除事件按逻辑删除、停用、解绑或归档处理，不允许物理删除业务数据。

## 10. 数据同步标准

同步任务必须使用 `integration_sync_jobs`，同步记录必须使用 `integration_sync_records`。

同步类型：

| 类型 | job_type |
|---|---|
| 首次全量 | `full` |
| 定时增量 | `incremental` |
| Webhook 补偿 | `event_repair` |
| 人工重试 | `manual_retry` |
| 夜间校准 | `reconcile` |

同步状态流转：

```text
pending -> running -> completed
pending -> running -> failed
pending -> queued
failed -> retrying -> running
running -> paused
```

每个同步 adapter 必须定义：

- 外部 API 清单。
- 分页或游标机制。
- 批次大小。
- 速率限制。
- 失败重试策略。
- 外部对象唯一键。
- 字段映射。
- 冲突处理。
- 删除/停用策略。
- 敏感字段处理。

同步写业务表前必须有租户约束。任何来自第三方的 `tenant_id`、组织 ID 或用户 ID 都不能直接信任，必须由租户连接反查得到。

## 11. 外部数据映射标准

所有进入底座的第三方对象必须保留稳定外部标识：

```text
external_source = {platform_code}
external_subject = {auth_subject_id}
external_id = {platform_code}:{auth_subject_id}:{object_type}:{object_id}
```

示例：

```text
wecom:ww123456:department:42
wecom:ww123456:user:zhangsan
dingtalk:dingcorp001:department:1001
```

业务表如果不适合直接加通用外部字段，必须提供映射表。映射表至少包含：

- `tenant_id`
- `platform_code`
- `provider_app_code`
- `tenant_connection_id`
- `object_type`
- `external_id`
- `local_object_type`
- `local_object_id`
- `last_synced_at`
- `status`

## 12. 组织和成员同步标准

涉及组织架构、成员、岗位、部门的第三方同步必须遵守：

- 第三方部门同步到本系统组织或部门前，必须先确定根部门映射。
- 部门移动必须按外部父子关系更新，不得只改名称。
- 第三方成员同步到本系统用户前，必须确定匹配策略。
- 手机号、邮箱可能不可见，不得作为唯一必填匹配字段。
- 第三方成员离职、删除或不可见时，本系统用户只能停用、解绑或标记离职，不得物理删除。
- 第三方部门删除时，本系统部门应停用或标记外部删除，不得物理删除已有业务引用。
- 同步不得覆盖本系统人工维护的关键字段，除非字段级策略明确允许。
- 每次同步必须保留批次、来源、操作者或触发源。

推荐匹配优先级：

```text
已有 external_id 映射
  -> 第三方 user_id/open_user_id
  -> 企业内唯一员工号
  -> 授权允许且经确认的手机号/邮箱
  -> 人工确认
```

## 13. API 网关代理标准

第三方 API 网关代理必须默认拒绝，按能力白名单开放。

每个代理 API 必须声明：

- 所属 `platform_code`。
- 所属 `provider_app_code`。
- 所属 `capability_code`。
- HTTP method。
- 外部 path 模板。
- 是否允许 query。
- 是否允许 body。
- 需要的 scope。
- 消耗的 quota code。
- 审计级别。

禁止：

- 前端传完整外部 URL。
- 前端传 access_token。
- 代理任意 path。
- 代理返回密钥、token 或第三方敏感响应头。
- 在日志中记录明文 query secret、token、credential_ref。

## 14. 权限、套餐与配额

第三方系统接入必须遵守：

```text
租户已开通 integration-center
  -> 套餐具备连接或同步能力
  -> 连接数配额未超
  -> 用户角色允许操作
  -> 第三方授权有效
  -> 执行绑定、同步或调用
```

标准配额：

| quota_code | 说明 |
|---|---|
| `integration_connection_count` | 租户连接实例数 |
| `integration_api_calls_daily` | 第三方 API 日调用量 |
| `integration_sync_records_daily` | 第三方同步记录日数量 |

新增特殊能力必须先在 `integration-center` Manifest 的 `quotas` 和 `package_features` 中声明，不得只在代码里硬编码。

## 15. 审计和日志

必须审计：

- 平台创建、更新、禁用。
- 服务商应用创建、更新、禁用。
- 凭证引用更新和轮换。
- 租户发起授权。
- 授权成功、失败、撤销。
- Webhook 验签失败。
- Webhook 事件入库、重试、死信。
- 同步任务创建、完成、失败、重试。
- 外部 API 调用失败。
- 配额超限。
- 管理员人工重放、暂停、恢复、解绑。

日志必须脱敏：

- `access_token`
- `refresh_token`
- `permanent_code`
- `client_secret`
- `suite_secret`
- `EncodingAESKey`
- `credential_ref`
- 手机号、邮箱等个人信息按业务要求脱敏展示。

## 16. 错误处理

错误必须可定位、可重试、可告警。

标准错误分类：

| 类型 | 处理 |
|---|---|
| 配置缺失 | 阻断上线或连接创建 |
| 授权失败 | 写租户连接失败状态和审计 |
| token 过期 | 自动刷新，失败后置 `refresh_failed` |
| 签名失败 | 拒绝请求，记录安全告警 |
| 幂等重复 | 返回成功，不重复处理 |
| 第三方限流 | 进入 `queued` 或 `retrying` |
| 字段映射失败 | 单条记录失败，批次继续 |
| 数据冲突 | 按字段策略处理，必要时人工待办 |
| 长期失败 | 进入 dead letter 或 alert |

## 17. 第三方 adapter 代码规范

平台专用逻辑必须放到 adapter 边界内。

推荐目录：

```text
internal/apps/integration_center/adapters/{platform_code}/
  adapter.go
  auth.go
  webhook.go
  sync.go
  gateway.go
  crypto.go
  types.go
  *_test.go
```

adapter 职责：

- 构造授权地址。
- 交换授权码。
- 刷新 token。
- 验签和解密 Webhook。
- 标准化事件。
- 拉取外部数据。
- 映射外部错误码。
- 生成同步记录。

adapter 不得：

- 直接绕过 service/repository 写业务表。
- 保存明文密钥。
- 读取其他租户连接。
- 直接操作菜单、权限、套餐。
- 把平台专用协议污染到通用 handler。

## 18. 交付文档要求

每个第三方平台接入必须提供独立文档，建议路径：

```text
docs/apps/integration-center/providers/{platform_code}.md
```

文档必须包含：

- 平台说明。
- 接入模式。
- 平台账号和后台配置步骤。
- 所需凭证和密钥引用，不写真实值。
- 回调 URL。
- 授权 URL。
- scope 或权限范围。
- 能力清单。
- 同步对象和字段映射。
- Webhook 事件清单。
- 配额和限流。
- 错误码映射。
- 上线检查。
- 回滚和解绑流程。

## 20. 企业微信软件服务商接入补充

企业微信软件服务商模式必须按第三方应用链路接入，不得按企业自建应用简化处理。

必须支持：

- `suite_ticket` 回调接收。
- `suite_access_token` 获取和缓存。
- `pre_auth_code` 获取。
- 租户管理员授权安装跳转。
- `auth_code` 换 `permanent_code`。
- 每个租户企业保存 `corp_id` 与 `permanent_code` 的安全引用。
- 每个租户企业获取 `corp_access_token`。
- URL 验证。
- `msg_signature + timestamp + nonce` 验签。
- `Token + EncodingAESKey` 解密。
- 通讯录部门、成员、标签同步。
- 通讯录变更事件增量同步。
- 应用卸载或授权变更后自动撤销连接。

推荐能力：

| capability_code | 说明 |
|---|---|
| `suite_authorization` | 第三方应用授权安装 |
| `department_sync` | 部门同步 |
| `user_sync` | 成员同步 |
| `tag_sync` | 标签同步 |
| `contact_event` | 通讯录变更事件 |

企业微信对象映射建议：

```text
corp_id -> integration_tenant_connections.auth_subject_id
corp_name -> integration_tenant_connections.auth_subject_name
permanent_code -> vault credential, DB only credential_ref
department.id -> external_id = wecom:{corp_id}:department:{id}
user.userid -> external_id = wecom:{corp_id}:user:{userid}
tag.id -> external_id = wecom:{corp_id}:tag:{id}
```

企业微信接入上线前必须完成一次测试企业真实授权、一次首次全量组织同步、一次通讯录变更事件增量同步和一次卸载/解绑回归。
