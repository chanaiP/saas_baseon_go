# 独立部署应用接入约束

## 1. 文档定位

本文档约束 `deployment_mode=STANDALONE` 的应用接入方式，面向 AI coding agent、后端开发、前端开发和交付人员。

独立部署应用指应用代码、运行服务、前端站点或任务进程不与 SaaS Baseon 底座同进程部署，但仍要接入应用中心、租户、权限、套餐、配额、审计、文档和版本治理。

任何 AI agent 在处理独立部署应用前，必须同时读取：

- `AGENTS.md`
- `CLAUDE.md`
- `docs/tech_design/业务开发标准.md`
- `docs/tech_design/应用中心接入强制规则.md`
- 本文档

## 2. 基本原则

- 独立部署不等于脱离底座治理。
- 独立部署应用必须拥有全局唯一且长期稳定的 `app_code`。
- 独立部署应用必须提供标准 Manifest，不能只在应用中心手工录入主档。
- Manifest 是菜单、操作、权限、API、套餐功能点、配额、客户端、文档和版本的持续声明源。
- 套餐中心功能点必须来自 Manifest 的 `package_features`，配额必须来自 Manifest 的 `quotas`。
- 未声明进入套餐的能力不得自动进入套餐中心；后续应进入套餐外订阅、非售卖或平台专属治理。
- 独立部署应用不得直接读写底座数据库、Redis、文件目录或内部表结构。
- 独立部署应用不得复用底座内部 JWT secret、数据库账号、Redis 密码或生产连接串。
- 前端隐藏、独立应用本地角色或本地菜单不能替代底座授权。

## 3. Manifest 要求

独立部署应用必须输出 `app.manifest.yaml` 或 `app.manifest.json`。推荐随应用仓库、制品包或发布流水线一并交付。

Manifest 必须包含：

| 字段 | 说明 |
|---|---|
| `manifest_version` | Manifest 结构版本 |
| `fragment_role` | 多文件片段角色，如 `main`、`frontend`、`backend`、`api`、`package` |
| `app` | 应用主档，含 `app_code`、名称、类型、来源、部署方式、可见范围、收费策略 |
| `clients` | 客户端形态，如 `PC_WEB`、`API_ONLY`、`WECHAT`、`DINGTALK`、`FEISHU` |
| `menus` | 底座侧菜单入口、排序、租户可见和套餐声明 |
| `operations` | 操作项和按钮能力 |
| `permissions` | 权限码、权限类型、平台专属、数据权限模式 |
| `apis` | 独立应用或底座网关暴露 API 的 method、path、权限和审计策略 |
| `package_features` | 进入套餐中心的功能点 |
| `quotas` | 配额项 |
| `documents` | 接入、部署、API、运维和版本文档入口 |

独立部署应用还应在 `app` 或扩展字段中声明：

- `deployment_mode: STANDALONE`
- `communication_modes`：`PLATFORM_API`、`WEBHOOK`、`DATA_SYNC`、`GATEWAY_PROXY` 中的一个或多个
- 应用健康检查地址
- 应用回调地址
- 应用 API 基础地址或网关路由前缀
- 需要的底座开放 API scope
- 数据同步方向和幂等键

## 4. 导入和同步

独立部署应用 Manifest 获取方式：

| 方式 | 约束 |
|---|---|
| 文件上传 | V1 默认方式；应用中心后端解析、校验、diff，不允许只在浏览器本地解析 |
| Git 仓库 | 必须声明仓库、分支、路径和访问凭证来源；不得把凭证写入 Manifest |
| 制品包 | 后端解包扫描 Manifest；必须限制大小、路径穿越和可执行文件风险 |
| 应用回调 | 独立应用通过开放 API 上报 Manifest；必须使用应用凭证和签名 |

导入规则：

- 数据库不存在 `app_code` 时，才允许走新建导入。
- 数据库已存在 `app_code` 时，只能走 Manifest 同步或升级。
- 扫描到多份 Manifest 时必须按 `app_code` 分组。
- 同一 `app_code` 多份 Manifest 必须声明 `fragment_role`，角色冲突时阻断。
- 主档、菜单 path、权限码、API method + path、套餐功能码、配额码冲突时必须阻断。
- 装载前必须展示 diff，明确新增、更新、停用、移出套餐、冲突和风险项。

## 5. 身份与鉴权

独立部署应用使用底座身份能力时，必须通过正式外部接入层：

- SSO/OIDC 或等价身份互认机制。
- 应用级凭证，如 `client_id`、`client_secret`、API Key 或服务到服务 token。
- scope 授权。
- 签名校验和时间戳防重放。
- token 轮换、吊销和审计。

禁止：

- 独立应用直接复用底座内部登录 token 签名密钥。
- 独立应用直接连接底座数据库校验用户或权限。
- 独立应用自行判断租户是否购买套餐后绕过底座校验。
- 把长期密钥、生产地址或真实客户信息写进 Manifest。

## 6. 权限、套餐与配额

独立部署应用运行时必须遵守：

```text
租户订阅有效
  -> 应用可见并已开通
  -> 套餐功能或套餐外订阅允许
  -> 角色权限允许
  -> 数据权限允许
  -> 配额未超限
  -> 独立应用执行
```

要求：

- 独立应用每个受保护 API 必须能追溯到 Manifest `apis.permission_code`。
- 底座网关代理模式下，鉴权、限流、套餐、配额和审计优先在底座执行。
- 平台 API 模式下，独立应用调用底座 API 前必须携带应用凭证和租户上下文。
- Webhook 模式下，底座与应用双方都必须校验签名、时间戳和幂等键。
- 数据同步模式下，增量游标、同步批次、失败重试和补偿必须审计。
- 未纳入套餐中心的能力不得在套餐矩阵里出现；如果可售卖，应走套餐外订阅或应用单独订阅。

## 7. 数据边界

独立部署应用可以保存自己的业务数据，但必须遵守：

- 所有租户业务数据必须有 `tenant_id` 或可等价映射的租户外键。
- 与底座同步的数据必须保留来源、版本、同步时间、幂等键和错误状态。
- 独立应用不得保存底座用户密码、token 明文、密钥或敏感连接串。
- 从底座同步的组织、用户、角色、套餐和权限数据只能作为授权快照或缓存，不能成为最终授权来源。
- 任何跨租户查询都必须有平台管理员或服务到服务授权，并记录审计。

## 8. 通讯模式约束

### PLATFORM_API

- 独立应用主动调用底座开放 API。
- 必须声明调用 scope、API 清单、租户上下文来源和失败重试策略。
- 不得调用未公开的内部 API。

### WEBHOOK

- 事件必须有事件类型、事件 ID、租户 ID、发生时间、签名和重放保护。
- 接收方必须幂等。
- 失败重试必须有上限和死信记录。

### DATA_SYNC

- 必须声明同步方向：底座到应用、应用到底座或双向。
- 双向同步必须声明冲突解决规则。
- 批量同步不得绕过套餐、权限和数据范围。

### GATEWAY_PROXY

- 流量先经过底座或网关。
- 底座负责认证、授权、套餐、配额、限流和审计。
- 独立应用仍必须做自身安全校验，不能信任未签名或未透传的上下文。

## 9. AI Agent 执行门禁

AI agent 处理独立部署应用时，必须执行以下门禁：

- 没有 Manifest，不得实现正式菜单、权限、套餐或配额同步。
- 没有 `app_code`，不得写任何应用主档、菜单、权限或套餐数据。
- 没有通讯模式，不得实现外部调用、回调或同步任务。
- 没有应用凭证和 scope 设计，不得实现服务到服务调用。
- 没有租户上下文，不得实现业务数据接口。
- 没有幂等键，不得实现 Webhook 或数据同步写入。
- 没有审计点，不得实现装载、授权、套餐、配额、Webhook 或数据同步变更。
- 不得把独立部署应用私有代码放进底座全局目录；合并部署代码才放 `internal/apps/{app_slug}` 和 `frontend/src/apps/{app_code}`。
- 如需为独立部署应用在本仓库提供适配器，只能放在应用中心、开放 API、网关、同步器或 connector 边界内，并明确不承载独立应用私有业务实现。

## 10. 验收清单

- Manifest 可被应用中心后端解析。
- 已存在 `app_code` 不能走新建导入，只能同步升级。
- Manifest diff 能展示新增、更新、冲突、停用和套餐变化。
- 菜单、权限、API、套餐功能点和配额都能追溯到 `app_code` 和 Manifest hash。
- 套餐功能点来自 `package_features`，配额来自 `quotas`。
- 独立应用调用底座 API 时有应用凭证、scope、租户上下文和审计。
- Webhook 或数据同步具备签名、幂等、重试和错误记录。
- 不泄露密钥、token、生产连接串或真实敏感数据。
- 后端测试覆盖 Manifest 解析、冲突阻断、权限拒绝和租户隔离。
- 文档包含部署、回滚、健康检查、API、事件、同步和运维说明。
