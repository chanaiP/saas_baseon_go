# 模块接入准入清单

新增或调整模块时，必须在评审和合并前完成以下声明与验证。该清单只约束底座接入标准，不要求新增业务能力。

## 必填声明

- 应用归属：`app_code`、应用名称、应用类型、应用来源、Manifest 路径。
- 工程目录：后端 `internal/apps/{app_slug}`、前端 `frontend/src/apps/{app_code}`；历史兼容模块需写明例外。
- 业务对象：表名、主键、逻辑删除字段、状态字段。
- 租户归属：`tenant_id` 来源、普通用户是否允许跨租户、平台管理员入口。
- 权限：菜单权限、按钮权限、API 路由权限矩阵。
- 权限归属：系统内置、仅平台、租户菜单、仅主体；是否允许进入套餐中心。
- 套餐：关联 feature code；不受套餐控制时写明原因。
- 配额：关联 quota code；不涉及配额时写明原因。
- 数据权限：资源类型、SELF/ORG/ORG_SUB/CUSTOM/BU 适用范围。
- 审计：模块名、动作名、对象 ID、结果、IP、UA、request_id。
- 测试：初始化、权限矩阵、租户隔离、逻辑删除、审计、前端门禁。

## 准入门禁

- 新应用没有 `app_code`、Manifest 或独立应用目录不得合并。
- Manifest 装载前必须校验应用、目录、菜单、权限、API、套餐、配额声明；不符合规范时必须拒绝装载。
- 应用装载必须按 `app_code` 同步底座菜单、角色权限资源、API 权限矩阵和套餐中心功能点/配额。
- 装载不得生成半成品数据；失败时必须回滚，并留下明确错误。
- 菜单、权限、套餐、租户菜单之间不得存在孤儿数据或重复数据。
- 平台专属能力不得进入租户套餐中心；仅主体能力不得作为租户可购买套餐能力。
- 受保护 API 未声明权限不得启动。
- 普通租户用户不得通过 path/query/body 伪造 `tenant_id`。
- 写操作必须有事务边界；关系表重建必须在事务内完成。
- 删除必须走逻辑删除、停用或归档；关系表物理删除需要写明例外。
- 前端按钮隐藏不得作为唯一授权来源，后端权限必须兜底。
- 菜单管理生成的能力进入套餐时，必须保持应用 -> 目录 -> 菜单 -> 操作树；套餐矩阵、创建主体套餐详情、角色权限配置必须一致。
- “查看”类能力默认由菜单访问和数据权限控制；没有真实按钮或独立接口授权需求时，不得作为操作项进入套餐。
- 平台侧“加入套餐中心 / 移出套餐中心”必须纳入权限体系，但该治理操作本身不得进入套餐。
- seed、Manifest 重装载和服务重启不得覆盖人工移出套餐、租户覆盖、套餐列配置和角色授权。

## 前端验收

- 页面刷新后，顶栏目录、左侧菜单、面包屑和当前路由必须一致。
- 列表页搜索区和操作区左右分离；搜索条件尽量一行展示。
- 重置按钮只在存在查询条件时显示，并能清空输入和选择。
- 分页必须以后端 `total` 为准；空页自动回退，不显示无数据但仍有虚假分页的状态。
- 表格、抽屉、弹窗不得出现无意义内滚动条或双滚动条。
- 操作列按钮在 Chrome、Safari 下均不得换行、越界或被遮挡。
- 弹窗必须使用统一标准组件样式，字段宽度不得越界。

## 文档验收

- 新应用必须补中文应用说明、Manifest 字段说明、菜单/权限/套餐/配额清单、API 清单、前端路由清单、测试用例。
- 菜单、权限、套餐或数据权限语义变化时，必须同步更新 `docs/tech_design/业务开发标准.md` 和本清单。
- 只改页面不改文档、只改 seed 不改装载规则、只改套餐不改菜单权限，均不得视为完成。
