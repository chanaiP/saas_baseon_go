# 业务单元 - 技术实现文档

## 1. 实现口径

业务单元模块重构为“业务基础对象登记中心”。

本轮目标不是继续扩展业务资源平台，而是将主对象收敛为业务单元：

```text
类型 -> 分组 -> 业务单元列表
```

数据字典只有一个业务单元字典类型，一级字典项表示类型，二级字典项表示分组。数据字典只提供可选范围；真实业务单元由用户登记。

## 2. 字典规则

字典类型建议统一为：

```text
business_unit
```

历史环境若存在 `business_unit_tree`、`business_unit_type`、`base_business.unit_scenario` 或 `base_business.unit_form`，统一由迁移写入 `business_unit` 后软归档旧字典；运行态不再 fallback 读取旧字典，不修改 `dict_type`、`dict_item` 表结构。

层级含义：

| 层级 | 说明 | 示例 |
|---|---|---|
| 字典类型 | 业务单元 | `business_unit` |
| 一级字典项 | 业务单元类型 | 门店、仓库、项目、业务线 |
| 二级字典项 | 类型下的分组 | 抖音、京东、华东、内部项目 |

读取时必须校验：

- 分组必须是所选类型的子项。
- 停用或删除的字典项不可用于新增。
- 不新增字典表，不改字典 schema。

## 3. 核心数据模型

### 3.1 业务单元主表

建议使用或改造 `business_unit` 作为主表。

核心字段：

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `tenant_id` | 主体 ID |
| `unit_type_code` | 一级字典项编码 |
| `unit_type_name` | 一级字典项名称快照 |
| `unit_group_code` | 二级字典项编码 |
| `unit_group_name` | 二级字典项名称快照 |
| `unit_name` | 业务单元名称 |
| `unit_code` | 业务单元编码，租户内唯一 |
| `parent_id` | 父级业务单元 |
| `attr_template_id` | 本次填写所使用的属性模板 |
| `attrs` | 自定义属性 JSON |
| `status` | 状态 |
| `remark` | 备注 |
| `deleted_at` | 逻辑删除 |

### 3.2 业务单元关系表

用于表达横向业务依赖。

| 字段 | 说明 |
|---|---|
| `source_unit_id` | 关系发起方 |
| `target_unit_id` | 关系目标方 |
| `relation_type_code` | 关系类型编码 |
| `relation_type_name` | 关系类型名称 |
| `status` | 状态 |
| `remark` | 备注 |

关系示例：

```text
门店 -> 使用 -> 仓库
抖音门店 -> 投放 -> 投放账号
项目 -> 关联 -> 门店
```

### 3.3 属性模板表

模板按类型和分组生效。

| 字段 | 说明 |
|---|---|
| `template_name` | 模板名称 |
| `unit_type_code` | 适用类型 |
| `unit_type_name` | 适用类型名称 |
| `unit_group_code` | 适用分组，允许为空 |
| `unit_group_name` | 适用分组名称，允许为空 |
| `sort_order` | 排序 |
| `status` | 状态 |

匹配规则：

```text
类型 + 分组模板优先
类型 + 空分组模板兜底
```

### 3.4 属性模板字段表

| 字段 | 说明 |
|---|---|
| `template_id` | 模板 ID |
| `field_key` | JSON key |
| `field_label` | 字段名称 |
| `field_type` | text、number、date、select、textarea、switch |
| `required` | 是否必填 |
| `default_value` | 默认值 |
| `placeholder` | 占位说明 |
| `options_json` | 下拉选项 |
| `sort_order` | 排序 |
| `status` | 状态 |

### 3.5 业务单元责任方表

用于绑定负责组织和负责人。

| 字段 | 说明 |
|---|---|
| `business_unit_id` | 业务单元 ID |
| `actor_type` | `org` 或 `user` |
| `actor_id` | 组织或用户 ID |
| `role_type` | `owner`、`operator` 等 |
| `include_children` | 组织是否包含下级 |
| `status` | 状态 |

前端复用 `OrgUserPicker.vue`，保存时按 key 前缀拆分：

- `c_`、`d_` -> `actor_type = org`
- `u_` -> `actor_type = user`

## 4. 页面实现

`BusinessUnitView.vue` 保持三块布局，但语义调整：

| 区域 | 新语义 |
|---|---|
| 左侧 | 业务单元类型 |
| 右上 | 当前类型下的分组统计 |
| 右下 | 当前类型 + 分组下的业务单元列表 |

右上卡片显示：

```text
抖音
3 家门店
```

新增按钮改为：

```text
新增业务单元
```

新增表单模块：

1. 基础信息：类型、分组、名称、编码、父级、状态、备注。
2. 自定义属性：自动匹配模板，也允许选择模板；按字段渲染控件，保存为 `attrs`。
3. 负责组织/负责人：复用 `OrgUserPicker`，非必填。
4. 关联关系：维护当前业务单元关联的其他业务单元。

## 6. 聚合规则

左侧类型和右上分组来自真实业务单元聚合，不直接展示字典全集。

```sql
SELECT
  unit_type_code,
  unit_group_code,
  COUNT(*) AS unit_count
FROM business_unit
WHERE tenant_id = :tenant_id
  AND deleted_at IS NULL
  AND status = 1
GROUP BY unit_type_code, unit_group_code;
```

右上分组卡片名称优先使用字典当前名称，业务单元表中的名称快照作为兜底。

## 7. 权限与套餐

业务单元仍挂在系统管理下：

```text
/business-units
```

建议权限：

| 能力 | 权限 |
|---|---|
| 页面访问 | `/business-units` |
| 新增业务单元 | `business_unit:create` |
| 编辑业务单元 | `business_unit:edit` |
| 归档业务单元 | `business_unit:delete` |
| 维护关联关系 | `business_unit:relation_manage` |
| 维护负责组织/负责人 | `business_unit:actor_manage` |
| 维护属性模板 | `business_unit:attr_template_manage` |

Manifest、菜单、权限、套餐功能点必须同步更新。业务单元不再新增独立“业务资源”左侧菜单。

## 8. 与现有实现的关系

当前代码中已存在 `business_resource` 相关实现。新口径下建议：

- 新页面主对象改回业务单元。
- `business_resource` 不作为页面主流程。
- 已实现的 actor、relation、field config 思路可迁移到业务单元维度。
- `resource_attrs` 思路改为 `business_unit.attrs`。
- `business_resource_field_config` 思路降级为业务单元属性模板和模板字段。

## 10. 本轮实现落位

后端按项目分层标准落位：

| 层级 | 文件 |
|---|---|
| GORM model | `internal/infrastructure/persistence/postgres/models/platform.go` |
| Repository | `internal/infrastructure/persistence/postgres/repositories/business_unit_repository.go` |
| Application service | `internal/application/businessunit/` |
| HTTP DTO | `internal/interfaces/http/dto/business_unit.go` |
| HTTP handler | `internal/interfaces/http/handlers/business_unit_base_handler.go` |
| Route / OpenAPI | `internal/bootstrap/api_routes.go`、`internal/bootstrap/router.go` |
| 权限矩阵 | `internal/interfaces/http/handlers/auth_policy.go` |
| Manifest | `internal/apps/system_management/app.manifest.yaml` |
| Frontend API | `frontend/src/api/businessUnit.ts` |
| Frontend view | `frontend/src/views/BusinessUnitView.vue` |

数据库增量迁移：

- `000080_business_unit_v3.up.sql`：业务单元字段、关系表、责任方表、属性模板表。
- `000081_business_unit_v3_permissions.up.sql`：菜单操作权限、套餐功能点、默认管理员角色授权。

接口返回统一走现有响应结构，`status` 使用现有整型状态：`1` 为启用，`0` 为停用。删除语义为归档/逻辑删除，不物理删除业务数据。

属性模板匹配规则已经实现为：

1. 优先匹配 `unit_type_code + unit_group_code`。
2. 未命中时回退到 `unit_type_code + 空 unit_group_code`。
3. 页面支持自动匹配，也支持手动选择模板；最终填写结果保存到 `business_unit.attrs` JSON。
