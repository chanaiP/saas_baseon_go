# 应用中心 V1 设计方案

## 1. 设计目标

应用中心 V1 的目标不是再补一个普通列表页，而是把应用作为底座治理的一等对象。所有应用通过 `app_code` 统一注册、装载、订阅、安装、授权、计入套餐、沉淀文档、记录版本和统计使用情况。

核心口径：

- 应用中心管应用定义、装载、资产、版本和治理。
- 套餐中心管租户是否拥有应用权益。
- 菜单管理管应用入口在租户侧如何展示。
- 角色权限管成员是否能访问和操作。
- 所有链路通过 `app_code` 串联。

## 2. 需求拆解

### 2.1 用户角色

| 角色 | 关注点 |
|---|---|
| 平台管理员 | 注册应用、装载 Manifest、维护客户端、入口、API、权限、套餐资源、文档、版本、体验邀请和运行治理 |
| 租户管理员 | 查看可见应用、开通应用、安装入口到菜单、下载客户端、给角色授权、查看试用和权益状态 |
| 租户成员 | 只看到已安装、已授权、权益有效的应用入口和客户端 |
| 开发/交付人员 | 通过 Manifest、文档池、版本记录和装载日志追溯应用来源与变更 |

### 2.2 应用来源

| 来源 | 说明 | V1 处理 |
|---|---|---|
| `BUILTIN` | 底座内置应用，例如应用中心、系统管理、系统监控 | seed 和 Manifest 双重登记，禁止绕开应用模型 |
| `MANUAL` | 手工创建的规划应用、占位应用、低代码应用、内部应用 | 允许先登记基本信息，再逐步补入口、权限、文档和版本 |
| `MANIFEST` | 真实代码应用通过声明文件装载 | 校验后同步应用资产，并写入装载记录 |

### 2.3 一级菜单和应用内二级菜单

应用中心一级菜单只保留公共入口：

| 一级菜单 | 说明 | V1 状态 |
|---|---|---|
| 应用列表 | 应用总览、筛选、创建、进入应用详情 | 必做 |
| 应用分类 | 管理应用类型、定位、分组口径；第一阶段可只使用字典，不单独做复杂页面 | 可后置 |

点击某个应用后进入应用详情，应用内二级菜单如下：

| 应用内二级菜单 | 说明 | MVP |
|---|---|---|
| 概览 | 基本信息、商业与开通摘要、当前版本、可见范围 | 必做 |
| 客户端管理 | PC Web、H5、移动端、桌面端、小程序、API Only 等入口和下载 | 必做 |
| 功能入口 | 应用菜单/页面/API Only 入口模板，后续安装为租户菜单实例 | 必做 |
| API 清单 | API 编码、方法、路径、权限码、Agent/外部开放状态 | 必做 |
| 权限点 | 应用访问、入口、操作、API、数据、Agent 调用权限 | 必做 |
| 套餐资源 | APP、CLIENT、ENTRY、API、PERMISSION、AGENT、QUOTA 资源 | 必做 |
| 文档池 | 需求、设计、API、操作手册、AI 生成记录，支持版本化 | 分阶段 |
| 版本发布 | 内测、Beta、正式版本和发布内容 | 分阶段 |
| 体验管理 | Beta、内测、邀请码、试用邀请和反馈 | 分阶段 |
| 使用情况 | 活跃租户、活跃用户、API 调用、功能点击、错误率 | 分阶段 |
| 功能日志 | 操作日志、API 日志、权限拦截、套餐拦截、装载日志 | 分阶段 |

### 2.4 可见范围

可见范围只保留两种：

| 值 | 说明 |
|---|---|
| `ALL_TENANTS` | 全部租户可见 |
| `SPECIFIED_TENANTS` | 指定租户可见，由平台人为选择租户列表 |

内部应用不需要特殊标识“内部租户”。内部租户只是被选择进指定租户列表的普通租户。

### 2.5 开通方式与收费方式

开通方式表示租户如何获得权益：

| 值 | 说明 |
|---|---|
| `PACKAGE` | 套餐开通 |
| `DIRECT_SUBSCRIBE` | 套餐外订阅 |
| `BUYOUT` | 一次性买断 |
| `FREE` | 免费开通 |
| `INVITE_CODE` | 邀请码开通 |
| `ADMIN_GRANT` | 平台管理员授权 |
| `BETA_INVITE` | Beta 邀请 |
| `TRIAL` | 试用开通 |

收费方式表示应用如何收费：

| 值 | 说明 |
|---|---|
| `FREE` | 免费 |
| `SUBSCRIPTION` | 订阅制，支持月/季/年 |
| `BUYOUT` | 一次性买断，永久有效，不做复杂版本买断 |
| `USAGE_BASED` | 按量收费 |

免费使用时间属于试用策略，可以叠加在订阅、买断、按量收费之上。

## 3. 分期建议

### 3.1 MVP 0：静态确认

当前阶段只输出设计方案和静态 HTML，用于确认：

- 一级菜单和应用内二级菜单是否正确。
- 应用详情页 Tab 是否完整。
- 平台侧和租户侧边界是否清楚。
- 商业与开通模型是否符合预期。

### 3.2 MVP 1：平台侧应用资产闭环

目标：不先做租户侧应用市场，先把平台侧应用资产建起来。

必做：

- 扩展 `sys_app` 字段：应用定位、可见范围、试用策略、开通方式、是否进入套餐、工作台展示等。
- 新增应用详情页，采用应用内二级菜单。
- 新增客户端、功能入口、API 清单、权限点、套餐资源的静态/可编辑数据模型。
- Manifest 装载解析先落到装载记录和应用资产表。
- 应用资源仍可向现有 `permission`、`saas_feature`、`role_permission` 做兼容同步。

### 3.3 MVP 2：租户权益与安装闭环

目标：租户能看到可见应用，能开通、安装、授权。

必做：

- 租户应用权益记录。
- 指定租户可见关系。
- 租户应用安装记录。
- 租户菜单实例。
- 运行时接口：应用入口、权限、权益。
- 访问判断：可见范围 -> 权益 -> 客户端 -> 入口安装 -> 角色权限 -> 状态。

### 3.4 MVP 3：版本、文档、体验和使用治理

目标：应用资产可追溯、可发布、可体验、可统计。

必做：

- 文档池主档、文档版本、变更记录、应用版本文档快照。
- 应用版本、版本变更明细、客户端版本包。
- Beta/内测/邀请码/试用邀请。
- 使用记录、计量项、功能日志。

## 5. 运行时判断

用户访问应用入口时按以下顺序判断：

```text
入口 entry_code
  -> 找到 app_code
  -> 应用是否可见
  -> 租户是否有有效权益
  -> 试用/订阅/买断/免费/邀请是否有效
  -> 当前客户端是否被权益包含
  -> 当前入口是否安装到租户菜单
  -> 用户角色是否拥有 permission_code
  -> 入口状态是否可访问
  -> 加载 component_key
```

返回态建议：

| 状态 | 页面提示 |
|---|---|
| 未可见 | 应用不可见 |
| 未开通 | 未开通应用 |
| 试用中 | 正常使用并显示剩余试用时间 |
| 试用到期 | 提示订阅、买断或联系管理员 |
| 订阅到期 | 提示续费 |
| 买断有效 | 正常使用 |
| 未安装 | 提示租户管理员安装应用 |
| 无权限 | 提示联系管理员授权 |
| 开发中 | 显示开发中占位 |

## 6. 接口设计草案

### 6.1 平台侧

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/apps` | 应用列表 |
| `POST` | `/api/apps` | 手工创建应用 |
| `GET` | `/api/apps/:id` | 应用详情 |
| `PUT` | `/api/apps/:id` | 编辑应用基础信息 |
| `PATCH` | `/api/apps/:id/status` | 启停应用 |
| `GET` | `/api/apps/:appCode/clients` | 客户端列表 |
| `PUT` | `/api/apps/:appCode/clients` | 保存客户端 |
| `GET` | `/api/apps/:appCode/entries` | 功能入口 |
| `PUT` | `/api/apps/:appCode/entries` | 保存功能入口 |
| `GET` | `/api/apps/:appCode/apis` | API 清单 |
| `PUT` | `/api/apps/:appCode/apis` | 保存 API 清单 |
| `GET` | `/api/apps/:appCode/permissions` | 权限点 |
| `PUT` | `/api/apps/:appCode/permissions` | 保存权限点 |
| `GET` | `/api/apps/:appCode/resources` | 套餐资源 |
| `PUT` | `/api/apps/:appCode/resources` | 保存套餐资源 |
| `POST` | `/api/apps/manifest/load` | 装载 Manifest |
| `GET` | `/api/apps/:appCode/load-records` | 装载记录 |

### 6.2 租户运行时

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/runtime/apps` | 当前租户可见应用 |
| `GET` | `/api/runtime/apps/:appCode/entitlements` | 当前租户应用权益 |
| `GET` | `/api/runtime/apps/:appCode/entries` | 当前用户可见入口 |
| `GET` | `/api/runtime/apps/:appCode/permissions` | 当前用户权限 |
| `POST` | `/api/tenant/apps/:appCode/install` | 租户安装应用 |
| `PUT` | `/api/tenant/apps/:appCode/entries` | 调整租户入口实例 |

## 7. 界面设计

### 7.1 平台端一级菜单

```text
应用中心
  应用列表
  应用分类
```

应用列表承担总览、筛选、创建、Manifest 装载入口。

### 7.2 应用详情页

应用详情采用左侧应用内二级菜单：

```text
商品中心 product-center
  概览
  客户端管理
  功能入口
  API 清单
  权限点
  套餐资源
  文档池
  版本发布
  体验管理
  使用情况
  功能日志
```

页面顶部固定展示应用名称、`app_code`、状态、可见范围、收费方式、当前版本和关键操作。

### 7.3 租户端

租户端不是管理所有应用资产，而是围绕“我能不能用、怎么安装、谁能用”：

```text
租户应用中心
  可见应用
  已开通应用
  已安装应用
  客户端下载
  邀请码开通
```

## 8. 静态原型

本设计对应静态 HTML：

```text
docs/prototypes/app-center-v1-static.html
```

确认静态原型后，再进入数据库、接口和 Vue 页面实现。
