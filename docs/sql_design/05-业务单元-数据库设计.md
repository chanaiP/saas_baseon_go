# 05-业务单元-数据库设计

## 1. 模块范围

业务单元模块用于登记基础业务对象，并维护：

- 类型和分组
- 父子层级
- 横向关联关系
- 自定义属性 JSON
- 属性模板
- 负责组织和负责人

数据字典只有一个业务单元字典类型。一级字典项作为类型，二级字典项作为分组。

## 2. 表清单

| 表名 | 说明 |
|---|---|
| `dict_type` | 字典类型，包含业务单元字典 |
| `dict_item` | 字典项，使用 `parent_id` 表达类型和分组 |
| `business_unit` | 业务单元主表 |
| `business_unit_relation` | 业务单元横向关联关系 |
| `business_unit_actor` | 负责组织和负责人 |
| `business_unit_attr_template` | 自定义属性模板 |
| `business_unit_attr_template_field` | 模板字段 |
| `business_unit_scope` | 角色业务单元范围，保留兼容 |

## 3. 业务单元字典

建议字典类型：

```text
business_unit
```

结构：

| 层级 | 存储方式 | 示例 |
|---|---|---|
| 字典类型 | `dict_type.code = business_unit` | 业务单元 |
| 一级 | `dict_item.parent_id IS NULL` | 门店、仓库、项目 |
| 二级 | `dict_item.parent_id = 一级.id` | 抖音、京东、华东 |

字典只提供可选范围，不代表真实业务单元。

## 4. `business_unit`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | 主键 |
| `tenant_id` | bigint | 主体 ID |
| `unit_type_code` | varchar(64) | 类型编码，一级字典项 |
| `unit_type_name` | varchar(128) | 类型名称快照 |
| `unit_group_code` | varchar(64) | 分组编码，二级字典项 |
| `unit_group_name` | varchar(128) | 分组名称快照 |
| `unit_name` | varchar(128) | 业务单元名称 |
| `unit_code` | varchar(64) | 业务单元编码 |
| `parent_id` | bigint | 父级业务单元 |
| `attr_template_id` | bigint | 属性模板 ID |
| `attrs` | jsonb | 自定义属性 JSON |
| `status` | varchar(32) | 状态 |
| `remark` | text | 备注 |
| `created_at` | timestamptz | 创建时间 |
| `updated_at` | timestamptz | 更新时间 |
| `deleted_at` | timestamptz | 逻辑删除 |

建议约束和索引：

- 租户内有效 `unit_code` 唯一。
- `tenant_id + unit_type_code + unit_group_code` 聚合索引。
- `tenant_id + parent_id` 层级查询索引。
- `tenant_id + status + deleted_at` 列表查询索引。

## 5. `business_unit_relation`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | 主键 |

| `source_unit_id` | bigint | 来源业务单元 |
| `target_unit_id` | bigint | 目标业务单元 |
| `relation_type_code` | varchar(64) | 关系类型编码 |
| `relation_type_name` | varchar(128) | 关系类型名称 |
| `status` | varchar(32) | 状态 |
| `remark` | text | 备注 |
| `created_at` | timestamptz | 创建时间 |
| `updated_at` | timestamptz | 更新时间 |
| `deleted_at` | timestamptz | 逻辑删除 |

有效关系唯一建议：

```text
tenant_id + source_unit_id + target_unit_id + relation_type_code
```


## 9. 聚合 SQL

类型和分组统计：

```sql
SELECT
  unit_type_code,
  unit_group_code,
  COUNT(*) AS unit_count
FROM business_unit
WHERE tenant_id = :tenant_id
  AND deleted_at IS NULL
  AND status = 'active'
GROUP BY unit_type_code, unit_group_code;
```

列表查询：

```sql
SELECT *
FROM business_unit
WHERE tenant_id = :tenant_id
  AND deleted_at IS NULL
  AND unit_type_code = :unit_type_code
  AND unit_group_code = :unit_group_code
ORDER BY updated_at DESC, id DESC;
```

## 10. 逻辑删除

所有业务数据不做物理删除。

业务单元归档前需要检查：

- 是否存在有效子业务单元。
- 是否被其他业务单元有效关联。
- 是否被业务数据引用。

不允许直接删除历史关系，需通过 `deleted_at` 逻辑归档。
